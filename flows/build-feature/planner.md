# planner

here is a feature to build. turn the spec into the behaviours it asks for,
each one something a test can check, and the file the code will probably go
in:

    - <the behaviour, with an input and what comes back> | <file>

anything the spec leaves open, say so on its own line rather than picking an
answer. the step after you writes the tests from this list, so a behaviour
missing here is a behaviour nobody tests.
