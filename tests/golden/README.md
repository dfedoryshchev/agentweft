# golden runs

Each file here is what one shipped flow did on one path (pass, gate fail, redo), replayed by `tests/test_golden.py` with the cli answering from a script: the steps, the gates, the journal and index lines, the handoff, the files left behind and what it printed. Times, run ids, seconds and temp paths are taken out before the compare. `risky-edit` is not shipped: it is a test flow in `tests/flows/`, there to pin a preflight park against a ranking the replay hands it: `hot-plan` parks before the worker on a plan that names a hot file, `hot-park` parks after it on a worker that touched one the plan did not name.

A case with `legs` runs `main()` once per leg, each leg a minute after the one before, and `--resume` picks up the run the leg before left; its `exit`, `raised` and `printed` are one entry per leg. `outage-resume` parks on a usage-limit reply with no tokens in it (a refused go, not a call) and the resume runs the step that got no answer. `capped` is a test flow with `max_calls: 1`: `budget-resume` parks before the reviewer, the plain resume is refused at the cap, and the resume with `--max-calls 2` finishes. `question-rides` is a patcher that asks a question whose `SIZE:` is no code: it rides in the handoff as a doubt and the run finishes through the patcher's gates. `chained-resume` is a resume of a resume: the last handoff carries the first leg's block and red proof, and each stop names the test it leaves red.

`suite-red` (fix-with-test, build-feature) is a change that turns its own test green and leaves another test in the suite red: the command gate fails it, sends the step back once, and the run stops on the second red suite.

`product-before-red` is a tests step that also edits product code: fix-with-test's worker is sent back once and the run stops, build-feature's tester puts the product file back on its second go and the run finishes. `no-red-proof` (fix-with-test) names a test the place already had, outside git, so nothing proves it red at the start and the patcher is refused before it is called.

Every way a run can end has a golden on every shipped flow: `done` and each cause in `runner/stops.py`, read off the flow's step lines, and `test_golden.py` fails when a flow has an end with no golden, so a cause added to the runner turns the suite red until a golden reaches it or `cannot()` there names why a replay of that flow cannot (`target moved` and `merge unchecked` need a git work tree, `overlap` a fanned-out step, `off task` a flow that turns the police on). The stop cases are built on each flow's `pass` case, stopping at the first step that can reach the cause: `no-answer` (every go empty), `tool-fault` (the cli refusing for good), `interrupted` (the run cut short while a step waits), `guard-refused` (a step leaves a `CLAUDE.md` in the place, so the next step is not started), `refused` (a `REFUSED:` line citing a spec line), `conflict` (a `CONFLICT:` line citing one), `no-verdict` (a reviewer that gives no verdict, on a flow with no gate to fail), `overlap` (a fanned-out task that writes a file no task named), and `ruling-resume`, `outage-resume` and `capped-resume`, each stopping to wait and then carried on to `done`; `code-review` has `journal: false`, so its `ruling`, `outage` and `capped` stop without a resume. The two code flows pin their own paths too: `wrong-test` sends a test back to the step that wrote it, `wrong-start-test` parks on a claim against a test the run started with, `escalated-resume` is the lead handing a question to the operator, `redo-stuck` is a reviewer still asking for a redo once the send-backs are spent, and `spec-rewrite` parks on a worker that rewrote a spec line.

`python -m pytest tests/test_golden.py --update-golden` writes the goldens that do not exist yet and leaves every existing one as it was: a golden that differs fails with its changed lines and the name to pass. `--update-golden build-feature/pass` rewrites only that golden and prints its changed lines at the end of the run; repeat the option or join names with `,` to rewrite more than one. A name with no golden behind it is refused, so put the test path before a bare `--update-golden`. A change that moves a golden path rewrites its golden in the same commit and says so; a new path adds its golden there too.
